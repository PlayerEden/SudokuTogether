# v0.2 solo / versus / local profile handoff

This work is stacked on `feat/local-coop-v0.1`, which remains draft PR #1 against `main`. Merge or validate that baseline first, then review this branch. The original project design document remains on `main`.

## Delivered implementation

- **Solo:** uses the existing uniquely solvable 9×9 Sudoku puzzles, local notes/number entry/clear/undo, tracked active solve time, saved/resumable solo state, completion recognition and persistent single-device records. The timer stops when the Activity backgrounds and resumes on return. Android configuration changes must not restart the timer.
- **Head-to-head:** `GameSession` adds mode `versus`, separate host and guest cell arrays, and an authoritative winner. The race cannot begin until both participants are active. Each competitor sees their own grid, plus the two progress totals. A validated completion decides the winner; later edits are rejected. Host and guest connect via the pre-existing local-network room discovery/code and TCP transport.
- **Answer confidentiality:** all state messages, welcomes, and embedded `Outcome.snapshot` payloads sent to the guest are filtered. The host is authoritative and necessarily holds both boards locally; this is friendly LAN play, **not** a cheat-proof network tournament or end-to-end encrypted match.
- **Profiles:** `LocalPlayerStore` uses Android `AtomicFile` for `LocalPlayerData`: a random device-local profile identifier, active solo state, and up to 500 completed-game records. Saving the completion and its score together makes recording idempotent. Co-op results are counted but currently have no solve-time measurement. A separate existing name preference remains.
- **Compatibility:** existing co-op save schema defaults to the original mode. Saved co-op host rooms use `host-session.json`; versus host rooms use `host-race-session.json` so neither overwrites the other; solo/local records live in `local-player.json`. The guest rejoin record remains `guest-session.json` for the last joined room.
- **Protocol:** the on-LAN message version advances from 1 to 2; both phones must run v0.2 to play together. Android version code advances from 1 to 2 and keeps the original package ID/signing identity.

### Two-phone acceptance checklist

1. Upgrade both phones with APKs signed by the same trusted app signing identity; confirm local records and v0.1 co-op saves survive the update. Do not put private signing keys in GitHub.
2. Start solo, enter a value, take notes, rotate device, background/return, leave and resume; verify actual active timer, board persistence, undo, and no duplicate time increments.
3. Complete solo puzzle; check personal profile, best time, unique record count; reopen app and verify durable results.
4. Host a **versus** race, join over the same Wi-Fi with six-digit room code. Verify neither phone can edit before both are active.
5. Enter different numbers into the same square on each phone; verify each player's entries remain independent. Both progress totals update without rival numbers/notes/selection leaking.
6. Finish a puzzle correctly on one phone; verify both phones agree on winner, loser is locked out, and each profile records the correct outcome only once.
7. Disconnect/reconnect the guest, background either app, and restart/resume the host. Confirm paused input, unchanged independent boards and correct token rejoining. Replace a rival and verify both grids reset.
8. Repeat v0.1 co-op shared entry/pencil marks/undo/rejoin/backup recovery. Try on small and large Android screens and screen rotation.
9. Inspect logs, socket payloads, private data files, and release signing configuration; ensure no credentials or opponent grids leak in LAN responses.

## Known limitations / next milestones

- **No real cloud accounts:** local identity/records cannot be recovered after uninstall or synchronized across phones. Later: secure auth, per-user stat storage, encrypted network rooms or an authoritative online service, and an opt-in migration/backup path. Do not claim leaderboards or verified online identities until implemented.
- **Race duration:** the recorded time is elapsed wall time between the rival's first admission and the result. Disconnect/background pauses editing but currently does not subtract paused time. Before competitive rankings, implement a host-authoritative active-race clock and fair tie/reconnect policy.
- **Sudoku variety:** only original Standard 9×9 puzzles are available. Difficulty tiers should be measured, not simply named. More board types can be a separate opt-in later without changing classic rules.
- **Co-op enhancements:** the previously discussed optional Split Clues, in-room text chat, square pinging, and contribution summary are **not yet found in the current v0.1 source branch**; audit and layer them deliberately rather than assume they are in production.
- The private repository's `main` branch does not yet contain the v0.1 Android app (draft PR #1). This v0.2 branch should stay reviewable as a stacked PR until baseline verification and merge.
