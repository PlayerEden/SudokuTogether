# Sudoku Together v0.8B — Human deduction & candidate calibration

Branch `feat/v0.8b-human-difficulty`, stacked on v0.8A `feat/v0.8-puzzle-foundation`. Draft PR #15. Issue #10.

## Human difficulty engine

`HumanSudoku.assess(Puzzle)`:

1. Confirms the puzzle is a legal, **uniquely solvable** classic 9×9 using the existing exact Sudoku solver. This is validation, **not** a human solving step.
2. Deduction-only trace with repeatable row/column/box scans:
   - Naked single
   - Hidden single
   - Locked candidate (pointing and claiming)
   - Naked pair
3. Tracks placements or candidate eliminations with affected squares/digits and a human-readable reason for eventual explanatory hints.
4. Stops with `BEYOND_CURRENT_LOGIC` if the next step requires unimplemented techniques. This is not evidence of non-uniqueness or an impossible puzzle.

**Provisional technique ceilings**: Easy requires only singles; Medium uses locked candidates; Hard uses naked pairs. A player-facing tier is **not** yet offered. Full difficulty also depends on number/complexity of deductions, presentation, and test-player experience.

## Verified initial calibration

Generated by the real Kotlin core solver on 2026-10-27, source from the CI build. Each clue floor uses **48 deterministic sample seeds (2001–2048)**. Exact-solution validation and reproducibility passed:

| Target floor | Easy | Medium | Hard | Beyond | Actual clue range | Generation + grading for 48 |
|---|---:|---:|---:|---:|---|---|
| 36 | 48 | 0 | 0 | 0 | 36–36 | 123 ms |
| 32 | 47 | 0 | 0 | 1 | 32–32 | 103 ms |
| 29 | 40 | 3 | 0 | 5 | 29–29 | 153 ms |
| 26 | 35 | 3 | 1 | 9 | 26–26 | 174 ms |
| 24 | 30 | 3 | 3 | 12 | 24–26 | 212 ms |

This small distribution is **not** a promise of production-grade balancing or mobile-device latency. It demonstrates that a lower clue floor by itself is **not** a reliable rating system, and a candidate search must validate the technique trace before assigning a label. Original `Sudoku.generate(seed)` still defaults to 36 and remains byte-for-byte identical for legacy seeds.

## Candidate-generation strategy (implemented but not enabled in menus)

`PuzzleSupply.nextRated(target, recentIds, seedProvider, maxAttempts)`:

- Easy: use original 36-clue floor, then require Easy technique trace.
- Medium: generate near 29 clues and accept **only** exact Medium.
- Hard: generate near 24 clues and accept **only** exact Hard.
- Reject repeated recent puzzle IDs, invalid solutions, unsupported grades, and unwanted tiers.
- Stop after at most 200 tries with a clear recoverable failure, **never relabel an easier board**.
- Work on a background thread when the Android selection UI is wired up in v0.8C.

The 48-seed data yielded Medium and Hard candidates. The next gate is broader seed samples, real-device latency, independent reference puzzles, and saved difficulty metadata before exposing the labels. Difficulty is not inferred from clue count alone.

## Compatibility and test gate

- No changes to saved models, multiplayer messages, production puzzle selection, gameplay controls or 2-phone rules in v0.8B.
- Updated Gradle and Android debug version to `0.8.0-dev2` with Android versionCode 9.
- Test coverage: known classic puzzle solved without guessing, duplicate/ambiguous rejection, repeatable traces, invariant checks, 48-board baseline and 240-board floor comparison, bounded generation and no-downgrade checks.
- New puzzle generation via `nextRated` intentionally remains behind a non-UI API until v0.8C.
