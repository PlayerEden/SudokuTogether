# GridMates v0.11B: launcher label and entry checking

The owner authorized the staged delivery plan and specifically requested **Sudoku** below the Android launcher icon. Keep **GridMates: Sudoku** in application/in-game branding and future store presentation. Preserve package, icon, signing, saves and other gameplay. Implement this as a launcher/activity label resource, leaving `app_name` and the existing component identity intact.

This first gameplay stage addresses the existing logical hint's inability to proceed when a previous player entry makes the visible grid impossible. Keep unlimited read-only logical hints. A failed hint does not count as assistance; show a concise dialog that offers **Check my work**. Also expose that optional action inside the normal hint dialog. Explain there that solution comparisons mark the puzzle Assisted. Checking is explicit, Solo/Daily only, and never silently diagnoses entries during ordinary play.

`SudokuAssistance.checkEntries(puzzle, visible): EntryCheck?` validates shape, digits, unchanged givens and the original puzzle's unique solution. It returns one of CONFLICT, INCORRECT_ENTRY, CORRECT_SO_FAR or NO_ENTRIES. Duplicate feedback uses normal row/column/box rules. For a non-duplicate wrong entry, test that entry against the original clues; return one suspect cell without revealing its correct digit. State truthfully that it does not match the puzzle's solution; do not invent a deduction. Null means the input cannot safely be checked. Never mutate input numbers or pencil marks.

Show the outcome in a scrollable native dialog, select the relevant editable square, and keep **Back to puzzle** available. For an incorrect entry, **Erase entry** is an explicit reversible action using the existing edit/Undo path. A positive check says the entries match so far, not that the puzzle is complete. An empty/invalid check gives no correctness service and is not counted.

Add optional `checksUsed: Int = 0` to SoloProgress and GameRecord, at the end of existing constructors. Count completed solution-comparison requests (incorrect entry or correct-so-far), separately from logical hints. Reopening a displayed outcome does not issue another request; repeated independent explicit checks may increase the counter. Counters saturate at9999 like existing hints but never limit help. Duplicate feedback, empty/invalid input and save failures do not increment checks. Persist a counted comparison before displaying its outcome. Undo cannot erase assistance history. Computed SoloProgress.assisted includes hints, checks and note assistance; saved results preserve the existing assisted/unassisted distinction and show check counts where relevant. Legacy fields default to zero and old records are not rescored.

Use the current generation/session/revision guards and store validation. Cancel stale work on navigation, never show Solo check information in a room, and clear feedback on selection/edit/new puzzle. Save failures show no comparison result and change neither accepted progress nor assistance count. Keep schema1/protocol5 and all LAN behavior intact.
