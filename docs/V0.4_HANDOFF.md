# Sudoku Together — v0.4 player identity & cooperative finish QA

This is a **draft / unbuilt** continuation on `feat/player-identity-v0.4`, stacked on the v0.3 local Wi-Fi chat and cosmetics branch. The predecessor PRs are still drafts; the primary branch does not contain these new features yet.

## Changes in this pass

- **Earned profile emblems**: six named styles, carried in the existing `Appearance` model with an optional default `emblem = "tile"`. No external font/image binaries or asset downloads are required. Shapes are represented using built-in text glyphs.
- **Progress-based achievements**: nine locally computed achievements from unique saved `GameRecord.id` entries. Includes first/five/twenty solo finishes, one/five completed co-op boards, one/three versus wins, five total races, and a Standard solo completion within ten **active** minutes. Records are deduplicated by match ID before progress is counted.
- **Profile collection**: available and locked emblems, live color/font/board previews, earned/target counters, and progress indicators. Profile identity cards show the player's name, equipped emblem, and title.
- **Multiplayer identity**: compact cards show both players' current emblems and titles on the same screen while the Sudoku board stays primary. Guest board values and pencil marks remain private in versus mode.
- **Co-op celebration**: solved co-op games display each participant's count of *final authored, filled entries*. This is **not** a score or a complete history of helpful work; erased/replaced notes do not count. Fixed starting clues remain neutral. Both contributors' equipped fonts/colors still appear on the completed grid.
- **Optional classic number display**: users can locally turn off mixed player glyph styles. This does not change the opponent's device, original cell ownership, saved puzzles, awards, or winner calculation.
- **Chat UX repair**: unread counts no longer continue climbing while the chat sheet is open. The physical keyboard should be checked in the two-phone acceptance pass.
- **Compatibility**: new serializable cosmetic fields have defaults to read older on-device sessions. The LAN message protocol version is **4** because wire payloads now carry the emblem. Android version is `0.4.0-dev`, `versionCode=4`; both phones must use the same app version for Wi-Fi play.

## Verification status

Updated UI smoke tests for the profile/collection/achievements and previous chat rate-limit assertions for lower test flakiness.

### Acceptance steps

Run locally (with JDK 17, Android SDK 35 and Gradle wrapper):

```bash
./gradlew :core:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Then test a correctly signed upgraded APK, including:

1. Existing v0.1/v0.2/v0.3 saved solo/co-op/race states survive upgrading to v0.4. Do not change the original signing identity.
2. Solve one solo puzzle, view the First Grid and First Sprout unlock, equip First Sprout, leave and restart. Check profile and persistent emblem.
3. Connect a second phone in co-op and versus. The other phone must display the correct emblem/title, not unknown custom values; opponent puzzle answers must not leak in versus network messages.
4. Host and guest each place several numbers on co-op grid. After completion, verify the *final-entry* counts and original clues. Test overwrite, Undo and a replacement partner.
5. Switch **Classic number display** on one phone and verify its board uses one readable number style while the other phone still sees authors' distinct colors/fonts.
6. Open/close chat, send while chat visible, then leave it closed and receive a message; test unread count, keyboard handling and rotation.
7. Verify screens at Android minimum supported font size and large accessibility scaling, especially 9×9 glyph bounds, scrollability and bottom sheet input.
8. Run all existing co-op and versus regression tests, including safe undo, stale move rejection, game save recovery and socket reconnect.

## Limitations before public release

- All cosmetic unlocks and achievements are computed from **local, device-owned** records. They are not cloud backed, fraud-resistant, transferable or authenticated between phones.
- No public player search, online matchmaking, leaderboard, store purchase, paid reward, custom avatars/uploads or chat moderation yet.
- Emoji/text glyph appearance may vary by Android font; artwork replacing these with purpose-designed drawable vectors is a later visual-polish step.
- Progress-based unlocks use the recorded 10,000-game history cap, not a separate lifetime aggregate. If a player finishes more than 10,000 games, older completions can fall out of the historical count. Add durable lifetime aggregates before promising permanent long-term achievement progress.
