**Branch:** `feat/v0.10b-daily-history-results`, draft [PR #22](https://github.com/PlayerEden/SudokuTogether/pull/22), based on verified `development` (v0.10A). **Current state:** full Android build **green** and **two independent Android emulator runs passed 10/10 tests**. ## Product changes

- The existing offline Daily Challenge is already playable in v0.10A; this pass **does not claim to have invented the daily feature**. It improves what was missing.
- **Accurate end-of-game summary** for completed standard Solo and Daily games: elapsed time, puzzle's recorded logical difficulty, number of moves, assisted/unassisted classification and hints used (when any). Values come from the matching saved game ID, not from estimates, unfinished data, or another Solo game.
- **Daily History** card in the offline profile: recent saved daily dates show status and elapsed time; tap **Continue** to resume an unfinished daily or **Review** to reopen a finished one. Six most recent appear first; Show all reveals the full saved list. Only an already-saved historical date may be opened; arbitrary backdating cannot create an old Daily Challenge.
- **Daily save retention safety:** the previous 31-entry window could drop unfinished daily progress; a proposed no-drop fix exceeded the existing load validator. Both are reconciled: up to 128 total saved Daily sessions, keeping *every unfinished day* within that capacity, and retaining at most the last 31 completed-board slots when space permits. On the 129th unfinished day, the app rejects creation with an explanation and keeps the previous saved work intact. Completed history records are stored separately and aren't erased when a reviewable completed board ages out.
- Daily puzzles remain versioned and date-deterministic Easy puzzles, locally generated and played without internet. Normal Solo save, records, achievements and head-to-head/co-op sessions are unchanged.
- Build version: `0.10.0-dev2`, code 14, test application ID suffix `.qa`, LAN wire protocol stays v5. Both phones must eventually run matching builds, but **physical two-phone testing is deferred at the user's request**, not passed.
