# v0.4 QA readiness — Sudoku Together

This is the manual verification package for the `fix/v0.4-build-readiness` branch, which is based on draft player-identity v0.4. **Source has not been compiled or device-tested yet**. These notes are instructions, not proof of a successful APK.

## Improvements in this branch

1. The race validator now verifies authoritative board owners, per-board fill counters, and claimed winners. A guest sees only their own entries; a host victory does not reveal host answers to the guest.
2. Every received room-chat line (including rejoin history) is validated for sender role, timestamp, message length, blank text, control characters and bounded identity.
3. LAN discovery and networking share `WIRE_PROTOCOL_VERSION = 4` instead of advertising stale NSD version 1. Rooms advertising a different protocol are excluded from the nearby list. Manual-address join still rejects incompatible handshakes.
4. After a completed match is recorded, subsequent chat/presence notifications no longer rewrite the identical local record to disk.
5. **Debug QA builds have a separate package ID** (`com.playereden.sudokutogether.qa`) and launcher name, **Sudoku Together QA**, so they install alongside the standard signed app. QA records are independent and may be lost if that QA package is uninstalled.
6. New regression cases exercise invalid chat history, spoofed/malformed messages, tampered race progress and unsupported victory claims.

## Build options

### On-demand GitHub Actions, only when you decide to spend minutes

1. Open the private `PlayerEden/SudokuTogether` repository's **Actions** tab.
2. Find **Sudoku Together — on-demand QA APK**.
3. Choose **Run workflow**, explicitly select branch `fix/v0.4-build-readiness`, and start the run.
4. When green, open the run's **Artifacts** and download `SudokuTogether-QA-<commit>`. Extract `SudokuTogether-QA.apk`; inspect its SHA-256 file.
5. Sideload the **same exact QA APK** on both phones, connecting both to the same Wi-Fi. The regular app remains separately installed.
6. If the job fails, read the uploaded **SudokuTogether-test-reports** artifact and logs instead of assuming an APK was built.

The workflow does not automatically run on pushes/PRs, does not require signing secrets, and has **not** been started by this handoff. A GitHub-hosted debug key can change between runs: do not assume a later QA APK can update a previous QA APK in place. If replacing a QA build requires uninstalling, only QA saves are affected. Never use a debug APK to replace the original signed release app.

### Local Android Studio / terminal

With JDK 17 and Android SDK 35 configured:

```bash
./gradlew :core:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Debug output should be `app/build/outputs/apk/debug/app-debug.apk`. It uses the independent `.qa` application ID.

## Two-phone acceptance checklist

- Install the same v0.4 QA APK on two phones. Test in both normal Wi-Fi and an internet-less Wi-Fi LAN.
- Host co-op, discover the room automatically, join with code, share notes and values, undo cross-player edits, disconnect and rejoin.
- Host versus, independently enter different values in the same position. Neither phone should see the other player's hidden numbers/notes, including after a move, undo, and completion.
- Race to complete a full valid board; verify **one** winner and both persisted win/loss records. Simulate disconnect/background and host restart.
- Open chat, send emojis/quick phrases and ordinary text. Confirm incoming counts while sheet closed and no unread increment while open. Rejoin and inspect bounded chat history.
- Complete solo puzzle, unlock an emblem, equip it, restart the app, enter a multiplayer room and verify the partner sees the badge.
- Toggle the classic-number accessibility option on one device, verify the other device keeps personalized colors/fonts.
- Review small screen layouts, Android font scaling, contrast, keyboard resize, and landscape/portrait state.
- Confirm the original non-QA app and its saved stats are untouched.
